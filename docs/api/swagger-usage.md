# Swagger UI usage

## Open the UI

Run Laravel with the desired host/port, then open:

```text
http://127.0.0.1:8010/docs/api
```

Use the same host and port for Swagger UI and the API. Before starting the server, make sure that host and port are included in `SANCTUM_STATEFUL_DOMAINS` and that `APP_URL` matches it; otherwise Sanctum will not attach session middleware to Swagger's same-origin requests. Clear cached configuration after editing `.env`. The specification is at `/docs/api/openapi.yaml`. The OpenAPI server uses the current origin instead of hardcoding a production URL.

The page uses Swagger UI `5.36.0` from unpkg.com. The browser needs internet access to download its CSS and JavaScript. The API schema itself is served from this application.

## Test a public endpoint

1. Expand **Session → GET `/api/v1/auth/csrf-cookie`**.
2. Select **Try it out**, then **Execute**. Swagger UI also calls this bootstrap when the page loads.
3. Expand **Session → POST `/api/v1/auth/login`**, select **Try it out**, and enter a test email/password.
4. Select **Execute**. The browser retains the session cookie automatically.
5. Expand **Session → GET `/api/v1/auth/user`** and execute it in the same browser tab/session.

Use **Try it out** and **Execute** on other operations to see the actual status and body. For profile-photo upload, select multipart form data and choose a test image.

Registration returns `201` when the verification notification is queued, not when it has reached an inbox. Run `php artisan queue:work database` in a separate terminal before expecting the local log mailer to write the verification message.

## What “Authorize” means for this API

The OpenAPI schema identifies the session cookie as the authentication mechanism. Browser JavaScript cannot set a `Cookie` header directly, so do not paste a session value or bearer token into Swagger UI. Execute login first; the browser-managed cookie is then sent automatically. The UI adds `X-XSRF-TOKEN` from the XSRF cookie to state-changing requests.

If a protected call returns `401`, execute login again in the same host/port. If a state-changing call is rejected for CSRF, reload the UI to bootstrap fresh cookies and sign in again.

## Signed email links

Email verification and pending-email verification require the full signed URL generated by the backend. Do not edit the `id`, `hash`, `expires`, or `signature` values. In local development with `MAIL_MAILER=log`, start the database queue worker and then copy the link from `storage/logs/laravel.log`. Signed links require `APP_URL` to match the server scheme, host, and port.

## Production and security

- Use HTTPS for production. The API intentionally rejects insecure HTTP in production.
- Keep secrets out of the OpenAPI examples. Use fictional test data only.
- Local Swagger assets come from a public CDN. If the documentation site must work offline or under a restrictive content-security policy, replace the CDN with explicitly approved, locally bundled Swagger UI assets.
